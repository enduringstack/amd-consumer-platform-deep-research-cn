# 内存、缓存、封装与互连：从 Ryzen DDR5 到 Instinct HBM

## 1. 性能不是“算力除以内存”这么简单

现代 AMD 平台是一组距离不同的存储层：寄存器最快最小，L1/L2 近核心，L3 在核心复合体或 3D 堆叠，DDR/LPDDR/GDDR/HBM 在封装内外，NVMe 与网络更远。每一层有容量、延迟、带宽、并发、功耗和一致性属性。程序的有效性能取决于数据是否在正确层、访问是否连续、预取是否成功，以及多个核心/设备是否争用。

带宽是单位时间可传输数据，延迟是一次请求等待时间。提高带宽不能消除依赖链上的单次延迟，减少延迟也不能给流式矩阵足够吞吐。游戏主线程和数据库指针追踪偏延迟，视频、GPU 着色和大矩阵偏带宽，编译与通用桌面混合。规格比较必须先归类负载。

## 2. CPU 缓存：命中率比标称容量更重要

每个 Zen 核有私有 L1 指令/数据和 L2，多个核心在缓存域共享 L3。L1 服务每周期高频访问，容量小；L2 承接较大工作集；L3 减少去 IOD/DRAM。缓存行通常按固定粒度移动，即使程序只读一个字节也会带入整行，因此连续数据结构比散乱指针更友好。

多核一致性保证核心看到符合内存模型的值，但修改共享行会在核心间转移所有权。两个线程更新同一缓存行的不同变量可能产生 false sharing，逻辑互不相关却互相使缓存失效。增加核心数后，这类同步流量会成为扩展上限。优化应从性能计数器确认，而不是盲目加预取。

Zen 3 后八核共享更大连续 L3，减少同 CCD 内跨复合体访问；跨 CCD 仍经过 IOD/Fabric。操作系统调度与线程池若频繁迁移，热缓存会丢失。低延迟服务可以把线程、内存和设备绑定同 NUMA，但绑核需要给中断和后台留资源。

## 3. 3D V-Cache：容量、热与调度的三角

3D V-Cache 通过垂直混合键合堆叠 SRAM，增加 L3 而不扩大计算裸片平面。[A029] 它特别适合“比普通 L3 大、比 DRAM 小”的复用工作集。缓存命中率从 90% 到 95% 看似只增加五个百分点，未命中次数却减半，因此延迟收益可能很大。

容量不是唯一变量。堆叠改变热阻，电压/频率策略可能不同；额外缓存访问也耗能；双 CCD 型号存在一侧大缓存、一侧高频的拓扑。游戏驱动和调度器识别工作负载后放置线程，若识别错误，跨 CCD 延迟抵消收益。稳定评测需说明芯片组驱动和 Game Mode。

对生产系统，缓存收益应以缺失率、内存带宽和端到端时长验证。若 DRAM 带宽显著下降且任务变快，说明缓存有效；若核心已满算或数据只读一次，增加 L3 无法创造复用。将所有游戏均值归因于“缓存越大越快”会掩盖引擎差异。

## 4. DDR4 到 DDR5：通道、子通道与训练

DDR5 提高传输率、每 DIMM 内部子通道并改进电源管理，AM5 桌面和新移动/服务器平台采用。标称 DDR5-6000 表示数据传输率，不是内存控制器时钟，也不是应用必达带宽。真实带宽扣除命令、刷新、行切换和控制器效率，延迟还包括时序周期与时钟换算。

桌面 Ryzen 通常双通道。每通道插一条 DIMM 更容易达到高频；四条 DIMM 增加载荷，主板可能降低官方速率。EXPO 是超频配置，不保证每颗 CPU、主板和内存组合稳定。长时内存测试应覆盖冷启动、热机、休眠唤醒与大容量，因为训练成功不等于无静默错误。

容量优先级取决于任务。容量不足导致换页到 SSD，损失远大于内存频率差；容量足够后，低延迟与带宽才有意义。游戏主机 32GB 通常提供余量，本地模型、虚拟机、视频和大型工程可能需要 64–128GB。ECC 能检测/纠正部分错误，但消费平台是否真正报告、主板是否布线和固件是否启用，必须逐项验证。

## 5. LPDDR5X：移动能效与不可升级

LPDDR5X 通过更宽封装内接口和低功耗状态服务 APU。它常焊接在主板附近，走线短、待机能效好，也能为 iGPU 提供带宽。代价是购买后不能扩容、维修牵连主板。标称 MT/s 高不表示 CPU 延迟一定低，内存控制器和封装拓扑仍不同。

Ryzen AI Max 的 256-bit LPDDR5X 是其大 iGPU 和共享内存的基础。[A051] 与普通 128-bit APU 相比，理论带宽显著扩大，但 CPU、GPU、NPU、显示和 I/O 共同使用。运行本地 LLM 时，模型权重顺序读取接近带宽限制；同时录屏、编译或游戏会争用，token/s 不能只由内存规格预测。

OEM 可以选择不同容量和速率，同一处理器不保证都配最高内存。低容量 SKU 会削弱“大共享内存”卖点；高容量价格可能逼近独显工作站。采购时记录可由 GPU 使用的最大 UMA、系统保留和 BIOS 设置，而不是只看焊接总容量。

## 6. GDDR6：独显的专用带宽

Radeon RX 用 GDDR6 通过多控制器和较宽总线提供显存。理论带宽等于引脚速率乘总线宽度再除八；实际访问受控制器、页面、压缩和缓存影响。Infinity Cache 减少外部流量，使较窄总线在命中时表现好，但缓存穿透场景仍受 GDDR 带宽。

独立显存把图形资产和系统内存分开。CPU 上传纹理需要经过 PCIe，GPU 访问未驻留数据会出现传输或分页。Resizable BAR/SAM 允许 CPU 映射更大的显存地址窗口，减少小窗口重映射；它不是把 PCIe 变成显存总线，也不保证每个游戏提升。[A054]

显存容量压力呈离散而非平滑：容量内可能稳定，超过后突然换页和卡顿。平均 FPS 不能揭示，需看低分位帧时间、PCIe 流量和显存驻留。纹理质量、光追加速结构、帧生成缓冲和创作应用都占显存。8GB、16GB、24GB 的价值随分辨率和生命周期变化。

## 7. HBM：把带宽搬到封装旁

HBM 将多层 DRAM 通过 TSV 堆叠，并在硅中介层或先进封装上以极宽接口连接 GPU，降低每比特能耗并提供 TB/s 带宽。[A034] 它适合 Instinct 的矩阵和 HPC，却成本高、封装复杂、容量受堆叠数量限制，不适合普通可更换 DIMM。

MI300X 的 192GB HBM3 允许较大模型留在单 GPU，MI350 系列把容量提高到 288GB HBM3E、带宽最高 8TB/s。[A034][A035] 这些是 GPU 本地物理内存，仍需主机、存储和网络供数。模型载入与 checkpoint 可能由 PCIe/网络限制，稳态矩阵才更接近 HBM 带宽。

HBM 带宽是多个堆栈并行的总峰值。访问不合并、Bank 冲突、缓存行为和计算占用会降低有效值。大模型推理常受权重读取带宽，训练还受矩阵算力和通信。不能用 8TB/s 直接除模型大小得到实际 token/s，因为每 token 的 KV cache、激活、调度和并发不同。

## 8. 统一地址、共享物理内存与一致性

“统一内存”可能指三件事：CPU/GPU 共享物理 LPDDR；不同内存具有统一虚拟地址；运行时自动迁移页面。三者不能互换。Ryzen APU 的 CPU 与 iGPU 使用同一物理 DRAM，但设备缓存、一致性和分配策略仍存在；独显可有统一虚拟地址，物理页仍在 GDDR 或主存。

零拷贝也常被误用。共享缓冲可以避免完整显式复制，但 CPU 写后 GPU 读仍需同步、缓存维护和格式转换；若设备访问远端页，带宽/延迟可能更差。正确优化是测量数据生命周期，尽量让生产者和消费者在合适设备上连续处理，而不是只删除 `memcpy`。

Ryzen AI Max 的共享内存让 CPU 前处理、GPU 推理和显示减少容量碎片，并能把较大模型交给 iGPU；但系统内存一旦被 GPU 占用，其他程序可用空间减少。操作系统可能压缩或换页，引发尾延迟。部署应留出系统、运行时和 KV cache 余量。

## 9. Infinity Fabric：CCD、IOD 与数据位置

Infinity Fabric 是可扩展连接框架，承载数据、控制和一致性；具体实现随 Ryzen、EPYC、Instinct 改变。[A030] 桌面 Ryzen 中 CCD 通过 Fabric 到 IOD/内存，跨 CCD 也经过封装路径。延迟由核心、缓存命中、Fabric 时钟、IOD 和 DRAM 共同组成。

早期 Ryzen 常讨论 FCLK、UCLK 与 MCLK 比例；DDR5 平台的最佳比例和上限已不同。过度追求频率会导致控制器分频或训练失败，纸面带宽提高但延迟变差。调优需同时看读写复制、随机延迟、真实应用与错误计数。

EPYC 有更多 CCD 和内存通道。内存页面应靠近使用它的核心，NIC/GPU DMA 也应靠近相应 NUMA。Linux `numactl`、hwloc 和性能计数器能验证；虚拟化需要把 vCPU、内存和直通设备对齐。错误亲和是多插槽扩展失败的常见原因。

## 10. PCIe：端到端路径而非版本标签

PCIe 是分层点到点互连，代际提高每 lane 速率。[A052] 一条 x16 链路的峰值是方向性总和前的单向数字，实际要扣编码和事务层开销。设备可能物理 x16、电气 x8；主板分叉后多个插槽共享 CPU 通道；芯片组设备还共享上行链路。

桌面显卡通常不持续填满高代 PCIe，因为工作集留在显存；显存溢出、GPU 计算频繁主机交换、外接 GPU 才更敏感。NVMe 顺序读峰值也不代表模型加载全程：文件系统、解压、CPU、页缓存和小文件会限制。

PCIe 拓扑决定 P2P。两张 GPU 在同一根复合体可能直接 DMA，跨 CPU/芯片组或受 ACS/IOMMU 时可能绕主存。工作站多 GPU 应用必须验证实际 P2P 和带宽，不因 Threadripper 有很多 lane 就假定软件启用。

PCIe 原子和 IOMMU 是 ROCm/RDMA 等功能的基础。Windows ROCm 文档指出现代 Zen 与 Intel Haswell 后 CPU 支持所需 PCIe atomics，但具体主板/设备/OS 仍要在支持矩阵内。[A039] BIOS 开关、Above 4G Decoding 和 Resizable BAR也会影响设备映射。

## 11. CXL：协议能力不等于产品可用性

CXL 建立在 PCIe 物理层之上，定义 CXL.io、CXL.cache 和 CXL.mem，用于设备发现、缓存一致与内存访问。[A053] 它可以让加速器一致访问主机内存，或让服务器扩展/池化内存。延迟和带宽仍受链路、交换和介质限制。

EPYC 平台支持某代 CXL 只证明根端口协议能力。真实部署还需要 CXL 设备、BIOS 枚举、ACPI 表、OS 内核、内存分层和 RAS。Type-3 内存扩展可能增加容量，却比本地 DDR 更远；数据库、内存缓存和 AI offload 需要页面放置策略。

消费 AM5 的 PCIe 5.0 不等于支持 CXL 内存设备。主板固件、CPU 产品合同和 OS 均可能未开放。不要因为物理插槽相同就插入未知 CXL 卡。CXL 也不是 Ryzen AI Max 的共享内存机制，后者在 SoC 内集成控制器和 LPDDR。

## 12. Smart Access Memory / Resizable BAR

传统 PCIe BAR 映射显存窗口较小，CPU 访问大资源需重映射。Resizable BAR 允许协商较大窗口，AMD 将匹配平台功能称为 Smart Access Memory。[A054] 它可减少驱动开销、改善某些资源上传，收益由游戏引擎和显存管理决定。

启用需要 CPU、主板 BIOS、UEFI、显卡 VBIOS 和驱动共同支持，通常还要求 Above 4G Decoding。CSM/旧式启动可能冲突。系统显示已启用后仍应逐游戏测试，有些负载提升小或出现回归，驱动会维护配置。

SAM 不是 GPU 直接以 DDR 带宽访问 CPU 内存，也不是把系统 RAM 添加到显存。CPU 访问显存仍经 PCIe；GPU 超出显存仍可能换页。它优化地址窗口，不改变物理链路。

## 13. USB4、外接 GPU 与扩展坞

移动 Ryzen 平台可实现 USB4，但具体端口是否支持 40Gb/s、PCIe tunneling、DisplayPort、充电和唤醒由 OEM 决定。一个 Type-C 形状不能证明全部协议。扩展坞多设备共享上行，显示、网卡、SSD 同时使用会争带宽。

外接 GPU 经 USB4/Thunderbolt 隧穿 PCIe，链路远小于桌面 x16，并有协议与往返延迟。外屏直连 eGPU 通常比把画面回传内屏更好。高端显卡更容易被链路限制，实际收益与游戏数据交换模式有关。

Ryzen AI Max mini PC 是否值得外接显卡取决于任务：游戏可获独显着色与显存，CPU—GPU 传输受限；AI 若模型常驻显存影响较小，数据预处理/多 GPU 通信较差。还要验证电源、驱动热插拔与睡眠恢复。

## 14. GPU Direct 与数据中心 DMA

数据中心希望 NIC、存储和 GPU 直接 DMA，减少 CPU 拷贝与内存往返。实现需要设备 P2P、IOMMU/ACS、驱动、注册内存和通信库共同支持。所谓“直接”仍有控制路径、队列和同步，不是 CPU 完全不参与。

Instinct 集群中，单节点 GPU 间高速链路负责高频集合，跨节点经过 NIC 和交换。若 NIC 与 GPU 跨 NUMA，数据可能穿过 CPU I/O 链；若消息太小，协议延迟主导；若拥塞，端口峰值无意义。性能诊断应从拓扑、单链路、双向、多流、集合到应用逐层测。

Pensando AI NIC/DPU 的价值是把包处理、拥塞和安全能力移近网络。[A063] 但 GPUDirect 类路径是否支持要查整个平台兼容清单，不能从网卡速率推断。固件和 OFED/驱动版本也需冻结。

## 15. Infinity Cache 与图形数据路径

Infinity Cache 是 GPU 片上大缓存，用于提高数据复用、降低 GDDR 流量。它与 CPU L3 都利用局部性，但图形访问模式和缓存结构不同。分辨率提高会增加像素、渲染目标和光追数据，缓存命中可能下降；无损压缩可减少外部带宽，但依赖数据可压缩性。

RDNA 3 的 MCD 将缓存和内存控制器分布在 chiplet，GCD 通过封装互连访问。互连需要提供远高于 PCIe 的内部带宽，同时控制功耗。外部看到的是统一显存地址，物理上却有多个控制器和缓存切片；驱动负责映射和负载均衡。

APU iGPU 通常没有同级独立大 Infinity Cache，依赖共享 L3/系统内存设计和较低功耗。比较 CU 数时必须把内存系统放入：相同 20 CU 在 128-bit LPDDR 与 40 CU 在 256-bit LPDDR 的供数不同；离散卡又有 GDDR 与缓存。

## 16. 存储到 GPU 的完整链路

本地模型加载路径是 NVMe → PCIe/芯片组 → 主机内存/页缓存 → GPU 内存或共享内存。文件可能经过解压、反序列化和权重转换，CPU 与内存会成为限制。APU 共享内存可以省去独显上传，但 SSD 数据仍要进入 DRAM；若内存不足，系统可能边读边换页。

游戏资产路径还包括 DirectStorage 类 API、GPU 解压和着色器。Xbox 固定平台能共同设计 NVMe、硬件解压和内存；PC 必须适配多种 SSD、CPU、GPU和驱动。[A074] 因此同样 SSD 标称速度，游戏加载差异可能很小或很大。

数据中心 checkpoint 路径可能经过并行文件系统和网络。训练暂停时间由每节点数据量、写入并发、文件系统元数据与压缩决定。HBM 更大意味着 checkpoint 可能更大，不能只扩 GPU 而不扩存储。

## 17. 内存容量规划

容量预算从不可压缩部分开始：操作系统与后台、应用代码、数据、模型权重、优化器状态、激活、KV cache、图形资产和安全余量。推理量化降低权重，但 KV cache 随上下文、层数、头维度和并发增长；训练优化器状态可为权重多倍。宣传“可运行某参数模型”若未注明量化、上下文和速度，意义有限。

APU 应为系统保留至少足够内存，避免把全部容量分给 GPU。独显系统应同时配置主存和显存；AMD Radeon ROCm 指南建议复杂 AI/ML 工作负载考虑 64GB 主存与 24GB 显存，并指出最低需求随工作负载变化。[A039] 指南不是每个模型的保证，而是部署起点。

服务器要按 NUMA 分配 DIMM，填满通道优先于只追求单条大容量。混插频率、rank、容量可能降速或不受支持。CXL 内存可做容量层，但软件需识别慢层。数据库与内存缓存还需要持久化和恢复预算。

## 18. 持续性能与能效测量

能效应以完成任务的焦耳衡量，不只看瞬时瓦数。低功耗机器运行更久可能消耗更多总能量，高功耗机器快速完成后进入空闲可能更省；也可能因电压频率曲线相反。测量需含墙上功率、空闲基线、任务时间和 PSU 效率。

内存能耗在大模型和多核服务器占比显著。更多缓存可能减少 DRAM 能量，HBM 每比特能效较好，LPDDR 适合待机；但更大容量本身有静态功耗。工作负载优化数据复用常比单纯降频有效。

热浸测试至少 30–60 分钟，记录 CPU/GPU/NPU 时钟、封装功率、内存带宽、温度、风扇和错误。掌机还记录电池放电与皮肤温度，机架记录冷却水与泵。峰值之后的稳定平台才是生产能力。

## 19. 故障与一致性

内存错误可能来自颗粒、信号、超频、温度或电源。ECC 能检测/纠正一定错误，不覆盖软件 bug、链路所有错误或控制器故障。消费主板即便支持 ECC UDIMM，也可能不报告计数；工作站/服务器有更完整 RAS 和日志。

PCIe 链路降级、AER 错误和重训练会造成性能波动。排查顺序应为恢复默认、检查插槽速率/宽度、固件、线材/转接、温度和设备日志。把每次 GPU reset 归因于驱动会漏掉电源与链路。

chiplet 系统需要隔离和恢复。AMD chiplet 白皮书把测试、互操作与故障隔离列为生态要求。[A030] 多裸片增加连接点，但也可通过分仓和冗余提高良率/可服务性；可靠性不能凭“单片更简单”或“chiplet 更先进”先验判断。

## 20. 端到端诊断清单

第一步画拓扑：CPU 核/CCD、内存通道、GPU、NIC、NVMe、根端口和交换。第二步验证配置：BIOS、通道填充、PCIe 宽度、Resizable BAR、IOMMU 和驱动。第三步测单层：缓存/DRAM、PCIe、显存/HBM、网络、存储。第四步测组合：CPU+GPU、GPU+NIC、存储+GPU。第五步才跑应用并用计数器解释。

若算力利用率低，先看等待的是内存、通信还是串行 CPU；若带宽低，看访问是否连续和并发够不够；若延迟抖动，看温度、分页、NUMA、后台和中断；若容量报错，区分物理不足、碎片、运行时保留和地址空间。端到端分析的价值在于把“AMD 驱动慢”“内存不够快”这种模糊结论拆成可证伪问题。
