# 从 K8、Bulldozer 到 Zen 5：AMD CPU、GPU、NPU 架构演进

## 1. 架构史应该回答什么

架构演进不是把代号按年份排成海报，而是解释每一代为什么改变、改变落在什么层级、产品为何仍可能表现不同。处理器性能近似受指令数、每指令周期和频率共同约束，但真实任务还会遭遇分支预测失败、缓存未命中、内存带宽、同步、操作系统调度、功耗和温度。GPU 也不能只数 CU：前端、纹理、光栅、光追、矩阵数据路径、缓存、显存和驱动都会改变有效吞吐。NPU 更依赖编译器能否把图划分为受支持算子。

因此本章把变化拆成五条线：CPU 核心、计算裸片与 I/O、缓存和内存、图形/计算 GPU、端侧 NPU。每条线都把微架构与具体产品分开。Zen 5 是 CPU 架构，Ryzen 9000 是产品家族，9950X 是 SKU，CCD 是裸片类型，AM5 是平台；把它们混为“一代”会产生错误的兼容性结论。[A003][A023]

## 2. K8：集成内存控制器与可扩展互连

K8 时代最值得保留的思想不是某一频率，而是把内存控制器从北桥移入处理器，并以点到点 HyperTransport 连接系统。这样做把核心访问本地内存的路径缩短，也让多插槽形成 NUMA：每颗处理器有更近的本地内存，访问另一插槽则跨互连。消费端感受到的是更直接的内存时延，服务器软件必须学习线程与页面亲和性。后来 Infinity Fabric、chiplet IOD 与多路 EPYC 仍沿用“数据位置决定代价”的原则。

K8 的 x86-64 扩展使 64 位通用计算进入大众 PC。它并不是简单增加寄存器位宽：更多通用寄存器、更大地址空间与新的调用约定一起改变编译器和操作系统。架构成功也提醒我们，ISA 兼容只保证程序语义，不保证相同微架构速度；老程序可以运行在新 Zen 上，却会因前端、缓存、分支和向量化差异展现完全不同的瓶颈。AMD 针对 Family 10h/12h 的软件优化指南仍把缓存、预取、内存访问和分支作为核心议题。[A024]

早期多核通过在同一封装集成核心，逐渐把共享缓存、一致性和内存控制复杂度带进消费端。此后每一次核心数增长都要回答三问：线程是否足够并行；工作集是否能被缓存；内存与互连能否供数。只看“核心翻倍”而不回答这三问，会高估桌面交互和游戏、低估编译与渲染，也会忽略许可证按核心计费的成本。

## 3. Bulldozer：共享模块的教训

Bulldozer 的核心组织试图在吞吐、面积和频率之间取新平衡。一个模块包含两个整数集群，却共享取指、解码以及部分浮点资源。营销上的“核心”计数与软件可获得的完整资源并非一一对应：两个线程竞争共享前端或浮点单元时，扩展不像两个独立大核；单线程又承受较长流水线和分支失败代价。这不是说共享资源必然错误，而是共享粒度必须匹配目标负载。

Family 15h 优化指南要求软件理解模块资源、调度、缓存和指令选择，这恰好说明“兼容 x86”不等于无需优化。[A024] Windows 调度器是否把两个繁重线程放进同一模块，会影响性能；编译器发出何种向量指令也会改变共享浮点路径压力。Bulldozer 后续 Piledriver、Steamroller 与 Excavator 逐步改良前端、预测和能效，却没能消除基本取舍给高性能桌面带来的印象。

这段历史对今天仍有两个意义。第一，核心数必须结合资源拓扑解释。Zen 5c 是面积优化核心，但不是 Bulldozer 式共享模块；Ryzen AI 300 某些 SKU 混合 Zen 5 与 Zen 5c 时，两类核心仍实现相同 ISA 语义，却在缓存、面积和频率目标上不同。第二，峰值频率只有在供电、温度和关键路径允许时出现，长流水线不能凭频率自动赢得每瓦性能。

## 4. Zen 1：重新建立独立核心与可组合单元

Zen 的战略转折是回到更强的独立 SMT 核心，并把四核 Core Complex 作为可组合单元。前端更强、分支预测和微操作缓存降低取指瓶颈，整数与浮点资源更均衡，SMT 让一个核心在部分流水线空闲时容纳第二线程。第一代 Ryzen 把高核心数重新带到主流桌面，但跨 CCX 访问的延迟、内存频率与 Fabric 时钟关系会显著影响游戏和延迟敏感负载。

第一代 Zen 也是平台学习期。内存训练、主板 BIOS、调度器和应用优化会让首发体验与成熟期不同。这形成一个贯穿 AMD 产品的规律：新硅只能定义能力上限，AGESA、BIOS、操作系统、电源计划和应用更新决定能力何时变为用户体验。评测必须注明固件日期；用首发旧 BIOS 代表整个生命周期，或用多年后调校代表首发状态，都不严谨。

Zen 的缓存层次和预取需要软件保持局部性。Family 17h 优化指南建议开发者关注数据对齐、分支、缓存冲突、预取和 NUMA，说明硬件并不能消除数据布局的重要性。[A024] 对消费者来说，“更快内存”的收益不是固定百分比：当任务被 GPU、存储、网络或纯计算限制时，内存变化可能很小；当核心频繁跨复合体或访问 DRAM 时，时序和 Fabric 才更关键。

## 5. Zen+ 与 Zen 2：制程改良到 chiplet 分离

Zen+ 主要通过工艺、延迟和频率管理改良第一代设计。Precision Boost 更细粒度地利用电流、温度与负载余量，揭示现代处理器并无单一“运行频率”：不同核心数、指令类型和散热条件会形成动态频率曲线。购买者应区分最大 boost 的短时单核条件与全核持续频率。

Zen 2 的决定性变化是把 CPU 计算核心放入 7nm CCD，把内存控制器、PCIe 与其他 I/O 留在单独 I/O Die。chiplet 让小计算裸片提高晶圆利用率，又可用不同数量覆盖 Ryzen、Threadripper 与 EPYC。AMD 的 chiplet 方法不是把裸片随意拼接；一致性、时钟、电源、测试、封装走线、固件和错误隔离都必须共同设计。[A030][A030]

CCD/IOD 分离也引入物理代价。核心访问 DRAM 必须经过 Fabric 到 IOD；多 CCD 之间共享数据也跨封装互连。对高吞吐多线程，这种代价常被更多核心和缓存掩盖；对延迟敏感、小工作集频繁共享的任务，拓扑可能决定性能。Zen 2 每个四核 CCX 共享一部分 L3，同一 CCD 内仍有两个缓存域，线程放置影响游戏与实时负载。

chiplet 的经济价值来自复用。高成本先进节点用于密集计算，成熟节点用于模拟/I/O，服务器可以增加 CCD 而桌面保留较少 CCD。产品分档还能利用部分核心或缓存有缺陷但其他功能良好的裸片。不过，外部观察者不能从家族名推断每颗 SKU 的所有裸片：APU 常用单片设计以降低移动功耗和封装占用，桌面 Ryzen 则多用 CCD+IOD。

## 6. Zen 3：统一八核缓存域

Zen 3 把一个 CCD 内八个核心组织为共享 32MB L3 的核心复合体，减少相邻核心访问另一半 L3 的边界。这对线程相互通信、游戏主线程与工作线程共享数据尤其重要。官方 Zen 技术入口把代际改进归入分支、执行和缓存，但实际产品收益还取决于频率、内存和软件。[A024]

统一缓存并不等于无代价的共享内存。L3 容量有限，多个线程仍会互相驱逐；跨 CCD 仍比同 CCD 更远；缓存一致性会消耗带宽。高核心数 Ryzen 9 和 Threadripper 的调度需要兼顾负载均衡与局部性。把线程固定到单 CCD 有时改善延迟，有时却浪费核心，因此不应把一种绑核技巧写成普遍优化。

Zen 3 也奠定 3D V-Cache 的软件基础：如果整个八核域可访问大容量 L3，堆叠缓存可让游戏工作集更长时间停留片上。首代 X3D 产品以频率与超频限制换缓存容量，说明架构优化总有预算约束。缓存容量增加不会提高 DRAM 物理带宽，只是减少去 DRAM 的次数。

## 7. Zen 4：DDR5、PCIe 5.0 与平台转换

Zen 4 把桌面平台转向 AM5、DDR5 和 PCIe 5.0，并为消费产品普及 AVX-512 能力。这里的 AVX-512 不能只按指令名判断实现宽度和吞吐；软件应通过特性检测和实测选择路径。更宽向量可以减少指令数，却增加功耗密度，并非所有持续任务都能保持最高 boost。

AM5 平台把插槽寿命、主板供电、I/O 和内存训练置于产品价值中心。CPU 支持 PCIe 5.0 不保证每块主板把同样通道接到显卡和多个 M.2；芯片组、布线、重定时器和固件共同决定可用拓扑。DDR5 标称传输率也不等于应用带宽，双 DIMM 每通道、不同容量颗粒和 EXPO 超频都会改变训练与稳定性。

Zen 4c 用更紧凑布局追求同面积更多核心，主要进入云服务器，随后也影响移动异构组合。它保留软件可见的一致 ISA，调度器不需要像 Arm 大小核那样在不同指令集间切换，但频率、缓存和功耗曲线不同。高密度核心适合大量并发，小量延迟敏感线程仍可能偏好全尺寸核。

## 8. Zen 5：加宽而不是单一参数翻倍

Zen 5 的官方描述强调更强分支预测、更宽流水线和向量路径、更大的乱序窗口；Ryzen 9000 产品页给出的代际 IPC 是厂商选定工作负载的几何平均，不能直接套到每个应用。[A002][A023] 更宽前端可以每周期把更多工作送进后端，更多执行端口和调度能力提高指令级并行，但前提是分支正确、数据已在近端缓存、指令之间有足够独立性。

Zen 5 的双管线取指/解码思想减少单一路径阻塞，改进预测降低错误路径浪费；更宽浮点和向量资源有利于科学、媒体与 AI 前后处理。与此同时，复杂后端提高面积和功耗，移动产品需要与 Zen 5c 混合，服务器则可用不同 CCD 面积密度服务高频与高并发。架构名相同不意味着桌面 CCD、移动单片与服务器 CCD 有相同缓存和频率。

Ryzen 9 9950X 是两个 CCD 加 IOD 的 16 核具体实现，Ryzen 7 9700X 是单 CCD 8 核 65W 档，二者都叫 Ryzen 9000，却面对完全不同的散热、线程和成本边界。[A007][A008] 9950X 更适合可扩展生产力；9700X 可能在轻负载、能耗和平台成本上更合理。最大 boost 是单核突发上限，不能和 170W/65W TDP 直接换算性能。

正式后续披露必须保持克制。AMD 若在 Financial Analyst Day 展示后续 Zen 名称、平台或时间范围，只能记录台上已发布信息。[A065] 没有数据表时，不推断核心数、缓存、节点、插槽或最终 SKU；合作伙伴路线图也不能代替 AMD 的产品可用性声明。

## 9. 3D V-Cache：把封装变成架构变量

3D V-Cache 通过垂直互连把额外 SRAM 堆叠到计算裸片，增加 L3 而不扩大 CCD 平面面积。[A029] 它的价值来自降低未命中率：大型游戏世界、模拟、EDA 和部分数据库若工作集处于几十到上百 MB，更多 L3 可避免高延迟 DRAM。若任务流式扫描远大于缓存的数据，或主要受计算单元限制，容量收益有限。

堆叠会改变热路径和频率预算。第一代产品把缓存放在核心上方，热量更难散出；第二代封装调整堆叠关系，提高频率和超频灵活性。不能因此断言所有 X3D 都比非 X3D 更节能：高命中任务会减少外部访问，低命中或高频生产力则可能由频率、核心数和功耗主导。

双 CCD X3D 还带来不对称缓存域。一个 CCD 有额外缓存，另一个可能保持高频。操作系统与驱动需要识别游戏和生产力偏好，将关键线程放到合适 CCD。调度错误会让理论优势转化为跨 CCD 通信。评价 9950X3D 一类产品必须注明 Windows 版本、芯片组驱动、Game Mode、BIOS 和后台负载。

## 10. 从 GCN 到 RDNA：图形效率路线

GCN 采用适合图形与通用计算的宽波前执行模型，长期覆盖 Radeon 与早期 Instinct。它在异步计算和通用性上有优势，但消费图形的每瓦、前端和缓存需要重新聚焦。RDNA 1 以新的 Workgroup Processor、Wave32 选项和缓存层次提高游戏效率，同时保留必要计算能力。软件波大小影响寄存器占用、分支发散和 SIMD 利用，不能只由 CU 数解释。

RDNA 2 引入硬件光线求交、Infinity Cache，并进入 Radeon RX 6000、游戏机和多代 APU。Infinity Cache 用较大片上缓存降低对外部 GDDR6 带宽的压力，作用类似“减少昂贵远端访问”，但高分辨率、光追和大纹理仍可能穿透缓存。Xbox Velocity Architecture 把定制 SoC、NVMe、解压与 API 串成数据路径，说明终端性能来自平台协同而非 GPU 单项。[A074]

RDNA 3 把高端 GPU 做成 Graphics Compute Die 与 Memory Cache Die 的 chiplet 组合。RX 7900 XTX 的产品规格应按整卡理解：GCD 执行图形，MCD 承担缓存与内存接口，GDDR6 容量、Infinity Cache、板卡功耗和显示引擎共同决定体验。[A015] GPU chiplet 的互连带宽与延迟需求不同于 CPU，不能把 CCD/IOD 经验直接复制。

RDNA 3.5 是面向 APU 的演进，重点是能效、媒体和集成环境；Ryzen AI 300 与 Ryzen AI Max 的 CU 在共享系统内存上运行。40 CU 的 Radeon 8060S 在规模上接近独显计算阵列，却没有独立 GDDR6，性能高度依赖 256-bit LPDDR5X、功耗分配与散热。[A006][A051] 同一 SoC 的 CPU 和 GPU 会争用封装功率与内存，因此 CPU 满载加 GPU 满载的持续结果不能由各自峰值相加。

RDNA 4 强化光追与 AI 路径，并与 FSR 4 的机器学习超分结合。RX 9070 系列的官方资料给出 4nm、PCIe 5.0、DisplayPort 2.1a 等产品字段，但厂商相对帧率仍依赖游戏、画质和驱动。[A014][A014] RDNA 4 的“AI 加速器”与 XDNA NPU不相同：前者位于 GPU，适合图形和高吞吐计算；后者以低功耗、受支持图为目标。

## 11. CDNA：从图形分叉的数据中心计算

CDNA 删除或弱化消费图形所需固定功能，把晶体管和功耗集中在矩阵、向量、缓存、高带宽内存和多 GPU 互连。它服务 HPC 与训练/推理，不是“没有显示输出的 Radeon”。软件使用 ROCm、HIP、数学库和通信库，部署单位往往是 OAM 模组、八 GPU 平台乃至机柜。[A036]

CDNA 2 的 MI200 采用多计算裸片和 HBM，面向 FP64 HPC 与矩阵；CDNA 3 的 MI300 将 CPU/GPU chiplet、IOD 与 HBM 的组合推得更深。MI300A 把 Zen CPU 和 GPU 放入统一封装用于加速计算，MI300X 则将资源集中给 GPU，提供 192GB HBM3，适合大模型容量需求。[A035] 两者名字接近，内存一致性和主机角色却不同。

CDNA 4 的 MI350 系列增加低精度格式和 288GB HBM3E、最高 8TB/s 理论带宽。[A034] “10.1 PFLOPS”之类数字只有在指定 MXFP/FP8、矩阵、稀疏与 boost 条件下成立；HPC FP64、训练 BF16 和推理低精度不可互换。大 HBM 也不消除通信：模型超出单卡、做数据并行或专家并行时，GPU 间与节点间网络仍决定扩展效率。

## 12. XDNA：端侧推理的新执行域

XDNA 源自 Xilinx 的 AI Engine 思路，由可编程计算阵列、片上存储和数据流互连组成。NPU 擅长持续、规则、可编译的张量图，以较低功耗处理摄像头效果、语音、背景分割和小模型。它不是可以任意运行 CPU 程序的通用核心，也不是大显存训练 GPU。

第一代 Ryzen AI 已进入 7040/8040 部分产品，XDNA 2 在 Ryzen AI 300/Max 提高 NPU 峰值至最多 50 TOPS并支持更丰富精度。[A005] 但“50 TOPS”只描述一条理论计算路径。实际图如果含未支持算子，会被切到 CPU/GPU；切分和张量拷贝可能吞掉收益；模型还需量化、编译和缓存。Ryzen AI Software 文档与 GitHub 示例才是判断模型可部署性的直接依据。[A041][A042]

Windows 应用可能通过 Windows ML/ONNX Runtime、DirectML 或厂商执行提供者选择 NPU/GPU；Linux 则依赖 XDNA 驱动与用户态组件。AMD 的开源 XDNA 驱动显示设备与队列接口正在进入 Linux，但源码存在不等于发行版、应用和所有 SKU 已支持。[A045] 端侧 AI 的体验应分四层验收：设备枚举、模型编译、正确性、持续功耗；只看到任务管理器的 NPU 图表不足以证明应用全程运行在 NPU。

## 13. Infinity Fabric：共同语言，不是无限带宽

Infinity Architecture 是 AMD 连接 CPU、GPU、缓存、内存控制器和加速器的技术集合。[A030] 在 Ryzen chiplet 中，Fabric 承担 CCD 与 IOD 的数据和控制；在服务器中，它扩展到更多 CCD、内存通道和插槽；在 Instinct 中还有 GPU 间链路。名称相同不表示各产品带宽、协议或一致性完全一样。

互连必须在延迟、带宽、功耗和封装走线间平衡。小数据、指针追踪关注往返延迟；流式访问关注持续带宽；一致性流量还会消耗链路。提高 Fabric 时钟可能改善某些内存延迟，却增加功耗并受硅和内存训练限制。对 Zen 2/3 的经验参数不能机械套到 DDR5 时代。

Infinity Fabric 也不等于软件看到一块无边界内存。多 CCD 共享地址空间，但缓存和访问距离不同；多 GPU 即便互连，显存通常仍由每个设备单独分配。程序需要显式选择设备、复制或用运行时管理统一虚拟地址。产品宣传中的“统一”必须继续追问物理位置、一致性、页面迁移和失败语义。

## 14. 从架构到实际持续性能

持续性能是一条闭环：工作负载产生指令和数据，硬件消耗电流，封装把热传到散热器，固件根据温度、电流、功率和可靠性调频，操作系统再调度下一批线程。任何环节达到限制，峰值都会下降。移动整机还共享 CPU/GPU/NPU 功耗预算，掌机更受皮肤温度、风扇噪声和电池容量约束。

验证 CPU 应至少记录单核、全核、内存和长时运行；GPU 记录平均帧率、低分位帧时间、显存、功耗、温度和时钟；NPU 记录编译成功率、端到端时延、CPU 占用和能量；混合任务记录资源争用。短跑测试可以发现峰值能力，却不能代表一小时渲染或长时间游戏。

架构升级带来的提升并非线性叠加。更强预测减少浪费，更多缓存减少 DRAM，chiplet 增加可扩展性，先进工艺提高密度；但每项都可能遇到新瓶颈。当 CPU 更快后，GPU 可能成为限制；GPU 更强后，共享内存或散热可能成为限制；NPU 更省电后，模型前后处理可能留在 CPU。深度分析的任务就是找出瓶颈迁移，而不是为每代写一个更大的百分数。

## 15. 架构判断清单

面对一个新 AMD 名称，依次问：它是微架构、裸片、封装、家族还是 SKU；CPU 核是 Zen 5 还是 Zen 5c，数量和缓存域怎样；GPU 是 RDNA、CDNA 还是没有；NPU 是否存在、属于哪代 XDNA；内存是可更换 DDR、焊接 LPDDR、独立 GDDR 还是 HBM；I/O 经 CPU 还是芯片组；功耗是默认、可配置范围还是峰值；软件支持矩阵是否点名该设备；OEM 是否实际启用；数据来自产品页、路线图还是测试。

这组问题能过滤多数营销误读。它也解释 AMD 的产品体系为何同时统一与复杂：统一的是可复用 IP 和软件方向，复杂的是每个市场对延迟、容量、带宽、扩展、生命周期、可靠性和成本的不同约束。
