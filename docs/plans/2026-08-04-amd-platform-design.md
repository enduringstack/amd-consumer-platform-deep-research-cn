# AMD 消费端与完整产品体系深度研究：设计说明

## 1. 目标与边界

本项目建立一个独立、公开、可复核的中文 AMD 平台研究仓库。研究快照冻结于 2026-08-04，主线是消费端 Ryzen、Ryzen AI、Threadripper、Radeon、掌机、迷你主机与半定制游戏机，同时把这些产品放回 AMD 的完整业务与技术体系中理解，包括 EPYC、Instinct、嵌入式与自适应计算、Pensando DPU、网络和软件生态。

项目不是购买榜单，也不把厂商峰值宣传当成跨平台结论。每个判断必须区分架构、裸片、封装、产品家族、具体 SKU、OEM 整机和测试配置；路线图只采用正式披露，未公开事项明确标成未知。

## 2. 可选组织方式与选择

方案一是单一长文。阅读连续，但难以独立维护规格、路线图和来源。方案二是纯产品数据库。适合筛选，却解释不了 chiplet、Infinity Fabric、内存层次、驱动和工作负载的因果链。方案三是“专题文档 + 产品矩阵 + 共享证据账本 + 自动合并”，兼具人类阅读、机器筛选和引用审计能力。本项目采用方案三。

## 3. 信息架构

`research/` 按问题域拆分：编辑口径、架构演进、消费产品、完整产品组合、内存与互连、软件和 AI、市场竞争、路线图与风险；`sources-amd.md` 保存编号化一手来源，`references.md` 解释引用方法与争议处理。`data/product-matrix.csv` 提供结构化代表产品矩阵。根目录合并版由脚本机械生成，不手工维护。

正文统一使用 `[A001]` 形式的引用标识。每个标识在来源账本中恰好定义一次，必须至少被一篇正文实际使用。第三方数据仅用于补充真实设备行为，必须保留平台、固件、功耗模式、测试版本和日期；无法满足时不进入确定性结论。

## 4. 分析框架

产品分析沿六层展开：微架构与 ISA；die/chiplet/IOD；封装、缓存与互连；具体 SKU 与功耗边界；OEM 散热和持续性能；软件、驱动和应用适配。横向比较采用“同任务、同精度、同功耗口径、同软件成熟度”的约束，不把 TOPS、TFLOPS、游戏帧率或模型吞吐直接混为一谈。

市场部分不伪造 TAM 数字，以 AMD 10-K、财报分部和公开出货信息为事实锚，讨论竞争位置、业务协同、渠道和切换成本。结论分成事实、条件性推断和待验证假设。

## 5. 数据流与质量门禁

研究流程为：官方发现页 → 稳定 URL 与发布日期 → 来源账本 → 章节引用 → 合并报告 → 自动审计。装配脚本按固定顺序拼接章节；检查脚本验证合并版至少 50,000 个汉字；引用审计检查正文无未定义引用、账本无未使用来源；重复检查排除标题和表头后检测长段落；链接检查对 404/410 作为硬失败，并允许对反爬或临时网络错误作非失败记录。

发布前执行 `git diff --check`、敏感信息扫描和全部门禁。设计与实施分开提交，最终在 `main` 分支推送到 `enduringstack/amd-consumer-platform-deep-research-cn`，再通过 GitHub API 验证仓库公开性、默认分支、远端 HEAD 与必需文件。

## 6. 已知限制

OEM 会修改功耗、内存、散热和 BIOS，同名移动 SKU 不代表同样体验。ROCm、Ryzen AI Software、Windows 驱动和应用支持会持续变化，本报告只能给出快照。未来架构若仅有路线图名称而没有正式规格，就只记录已披露的定位与时间窗口，不反推核心数、制程或性能。
